# Eine einzige exponierte API für alle Aufrufer, inklusive OTP-Fallback

Erziehungsberechtigte ohne Entra-ID-Zugang brauchen einen Zugriffsweg auf die Daten ihrer eigenen Schüler. Statt eines zweiten Backend-Vermittlers mit eigenem Zugriff auf die Datenbank (so ursprünglich in `project-parts.md` Abschnitt 9 skizziert: „nicht direkt über die Haupt-API") ruft die Azure Function des externen Frontends (Azure Static Web App, `project-parts.md` Abschnitt 9) dieselbe `wb-backend`-API auf wie jeder interne Entra-ID-Nutzer — authentifiziert über ein eigenes, kurzlebiges, auf den Fallback-Pfad beschränktes Token (OTP-Fluss, `idea/04-identitaet-zugriff.md`), nie über einen direkten Datenbankzugriff. Die PostgreSQL-Datenbank bleibt für jeden Aufrufer ausschließlich über das interne Docker-Netz erreichbar, unabhängig von der Zugriffsquelle (`idea/03-container-anwendung.md`).

Grund: eine einzige exponierte Schnittstelle statt zwei getrennter Zugriffswege hält Auth-/Ownership-Check-Logik an einer Stelle (`rules.md` Abschnitt 3, „eine Konfigurationsquelle pro Sachverhalt") und öffnet keinen zweiten Netzwerkpfad in die Vertrauensgrenze hinein (`rules.md` Abschnitt 2, Zero-Trust).
